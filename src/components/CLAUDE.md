# src/components — Shared components

Reusable, app-wide UI. `ui/` is reserved for shadcn/ui primitives (generated by the CLI,
never hand-written — use the `add-shadcn-component` skill).

## When code belongs here

- Used by 2+ pages or features -> it is shared, put it here.
- Used by a single route -> keep it colocated with the route (or in its feature folder).
- Belongs to a business domain (billing, auth, ...) -> it goes in
  `src/features/<name>/components/`, not here. This folder is for generic UI only.

## Authoring standards

- Files in kebab-case: `invoice-table.tsx`, `page-header.tsx`. One component per file,
  named export.
- Type props with an `interface` named `<Component>Props`; destructure in the signature.
- Server Component by default; add `"use client"` only for state, effects or event handlers.
- Variants with CVA (`class-variance-authority`, already a dependency) instead of prop-driven
  ternaries. Merge classes with `cn()` from `@/lib/utils`.
- Accept `className` and merge it last, so callers can adjust spacing/layout:
  ```tsx
  interface PageHeaderProps {
    title: string;
    className?: string;
  }

  export function PageHeader({ title, className }: PageHeaderProps) {
    return <h1 className={cn("text-2xl font-semibold", className)}>{title}</h1>;
  }
  ```
- Colocate a test (`page-header.test.tsx`) for any component with logic or variants.
  Purely presentational one-liners don't need one.

To scaffold a component, use the `create-component` skill.
